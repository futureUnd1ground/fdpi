# Движок FDPI 0.3.0

Внешняя зависимость: [zapret2](https://github.com/bol-van/zapret2),
commit `9b9b929f837978173d787a5773a47a91d90f7f81`, MIT.
Изучено [руководство](https://github.com/bol-van/zapret2/blob/master/docs/manual.md)
и CLI собранного движка 2026-11-08.

В zapret2 C-движок отвечает за перехват, распознавание и сборку протоколов;
Lua-функции задают преобразования пакетов. FDPI не переносит исходный код
zapret2 в свои Go-пакеты. Неизменённые nfqws2 и стандартные zapret-lib.lua,
zapret-antidpi.lua собираются/устанавливаются как отдельные зависимости.

Собственная реализация FDPI: ограниченная JSON-модель, компилятор профилей
в аргументы API, жизненный цикл процесса, правила nftables, TUI, установщик,
диагностика и проверка данных API YouTube. Произвольный Lua из JSON не выполняется.

## Компиляция

- Существующие ID стратегий и пользовательские домены сохраняются.
- `fake` преобразуется в отдельные вызовы для http_req и tls_client_hello,
  с соответствующими встроенными blob. badseq означает tcp_seq=-10000,
  md5sig — tcp_md5; TTL распространяется только на fake.
- multisplit/multidisorder получают проверенные маркерные позиции.
- HostCase применяется только к http_req, QUIC — только к quic_initial.
- Входящее направление не вызывает Lua (`--in-range=x`). Последний профиль
  пропускает неподходящие домены без преобразований.
- `--fwmark=0x20000000` совпадает с исключением в таблице FDPI.
- `--bind-fix4` и `--bind-fix6` сохраняют исходящий интерфейс при rawsend.
  Без них повторная маршрутизация может отправить сегменты прямого соединения
  в VPN с меньшим MTU. Это не отключает kill switch другого приложения.
- `--dry-run` проверяет аргументы. Это не подтверждение работы Lua на пакетах:
  для этого отдельно запускаются сетевые тесты с настоящим nfqws2.

Пути: `/usr/lib/fdpi/nfqws2`, `/usr/lib/fdpi/lua/zapret-lib.lua`,
`/usr/lib/fdpi/lua/zapret-antidpi.lua`. Исполняемый файл и Lua-зависимости
перед административным запуском проверяются на владельца root и отсутствие
групповой/общей записи. Старый `/usr/lib/fdpi/nfqws` не используется.

## Сеть и ограничения

FDPI владеет только таблицей inet fdpi с меткой fdpi-managed-v1.
NFQUEUE 24000, локальный output, первые 20 TCP / 12 UDP пакетов по conntrack.
Глобального flush, отключения IPv6 и автоматического изменения чужого firewall нет.
Нужен явно включённый net.netfilter.nf_conntrack_acct=1.
Queue bypass обеспечивает прямую передачу при отсутствии слушателя; он не
исправляет неподходящую стратегию при живом движке. При аварии/остановке
супервизор удаляет свою таблицу; systemd ExecStopPost повторяет cleanup.
Готовность определяется по PID-файлу после инициализации очереди.

Сетевые тесты проверяют полные HTTP/HTTPS данные IPv4/IPv6, реальное разделение
пакетов и сохранение интерфейса при конкурирующем маршруте fwmark с MTU 1376.
Они не моделируют оборудование конкретного провайдера и не доказывают обход DPI.
