## Что проверяют namespace-тесты

1. Отказ изменять чужую таблицу inet fdpi без ownership marker.
2. Сохранность отдельной чужой таблицы inet unrelated.
3. nft --check, применение, атомарная замена и идемпотентная очистка.
4. Два отдельных namespace и veth между ними; HTTP/80 и TLS/HTTPS/443 сервер.
5. Точная передача 90 112 байт ответа по IPv4 и IPv6 для Light, Balanced,
   TLS Focus. TLS-проверка включена: доверие к CA только локального тестового
   сервера, без InsecureSkipVerify.
6. AF_PACKET захват исходящего IPv4 TCP на veth: настоящий Light split с
   payload длиной 1 байт как для HTTP, так и для TLS ClientHello.
   Например: HTTP={1,110}, TLS={1,24,64,67,133,1447}; отдельные короткие TLS
   пакеты включают handshake/close_notify, не все являются desync-фрагментами.
7. Ненулевые nft queue counters, отсутствие потери точного HTTP/HTTPS payload.
8. nft bypass сохраняет HTTP/HTTPS при отсутствии слушателя NFQUEUE.
9. Штатная остановка и SIGKILL настоящего nfqws: супервизор завершает работу,
   собственные правила удалены. Повторный запуск проходит.
10. Неверная стратегия и отсутствующий executable не принимаются.
11. Flock отвергает повторный запуск/параллельную привилегированную операцию.

Отдельный unit test транзакции применения намеренно проваливает restart callback
и проверяет восстановление предыдущего файла и вызов восстановления службы.
Это проверка алгоритма rollback, **не** реальный сбой systemd на основной системе.
Диагностические тесты используют локальный TLS-сервер, проверяют отклонение
недоверенного сертификата, разделение DNS/TCP/TLS ошибок и транспортно достижимый
HTTP 451. Нет подмены TLS/HTTP успеха на успех обхода.

## Не проверено / ограничения

- Установка/удаление с root на основной машине: sudo требует пароль.
- Реальный systemd start/restart, сигнал Notify, sandbox, rollback при его
  отказе, автозапуск и восстановление после перезагрузки.
- Сборка полноценного Arch package через makepkg; проверены исходник и bash syntax.
- Реальные DPI провайдера, Discord voice, YouTube video, Telegram MTProto,
  Steam/game traffic, QUIC/HTTP3 payload. Сухая проверка QUIC argv не доказывает
  работающий QUIC bypass.
- Запуск Strategy Lab с перезапусками установленной системной службы. Его
  HTTPS probe и rollback primitive проверены отдельно, orchestration — нет.
- Статистически устойчивый подбор стратегии, active traffic watchdog и throughput.
- TLS record fragmentation, cgroups/process isolation, router forwarding,
  nfqws2/Lua adapter, автоматическое скачивание обновлений.
- Автоматическое восстановление Lab после SIGKILL/power loss: defer при них
  не выполняется. Обычный SIGINT/SIGTERM обрабатывается; при жёстком завершении
  проверьте конфиг и используйте rollback. Журнал восстановления пока отсутствует.
- Отдельный запуск Kitty/Alacritty/foot и самих wallust/pywal/matugen.

Ни основной nftables ruleset, ни systemd units, ни sysctl основной машины в ходе
проверок не изменялись. Пакетный обход подтверждён для тестовых endpoint в изоляции;
успех обхода блокировок на подключении пользователя не заявляется.

## Интерактивная установка

`fdpi setup` теперь выполняет пошаговый мастер, а прежняя статическая инструкция
перенесена в `fdpi setup --guide`. Добавлен запуск по `i` из интерфейса.

После изменения прошли `make check` (gofmt, vet, unit tests, race detector),
сборка и `bash -n` установочных скриптов/PKGBUILD. В реальном PTY проверены:
поиск исходников из другого каталога, показ зависимостей и команды pacman,
выход через q до привилегированных действий, открытие мастера из TUI и возврат.
Также проверены `--help`, `--guide` и отказ интерактивного запуска без терминала.

Unit tests управляющей логики используют подставленный executor: отмена/EOF
не запускают команды; после ошибки последующие команды не выполняются; retry
повторяет только упавшую команду; готовый компонент можно пропустить. Эти тесты
не являются настоящей установкой пакетов или end-to-end проверкой всей установки.
Отдельные файловые тесты проверяют создание sysctl-конфига во временном каталоге,
идемпотентность, сохранение чужого содержимого и отказ от символических ссылок.

Привилегированные действия ограничены фиксированными admin accounting-on и
accounting-persist. Они меняют только net.netfilter.nf_conntrack_acct и фиксированный
/etc/sysctl.d/70-fdpi.conf. Установка файлов и helpers используют operation lock.
Полный сценарий с pacman/sudo, runtime sysctl на основной машине, системной
установкой, первым запуском и автозагрузкой в этой сессии не выполнялся.
Основной firewall и системные настройки в ходе проверки не изменялись.

## Исправление зависимости zlib в CachyOS

Выявлен конфликт прямого `pacman -S zlib` с установленным zlib-ng-compat.
Мастер теперь получает только неудовлетворённые зависимости через `pacman -T`,
учитывая виртуальные Provides. Код 127 означает отсутствующие зависимости;
другие ошибки останавливают мастер. Имена проверяются по фиксированному списку
перед передачей sudo/pacman. В ручных командах убран принудительный запрос zlib.
Зависимость zlib в PKGBUILD сохранена: pacman удовлетворяет её установленным
провайдером, а не требует заменять его конкретным пакетом.

На фактической системе zlib-ng-compat 2.3.3-2 предоставляет zlib и libz.so.
`pacman -T` из всего списка FDPI вернул только libnetfilter_queue. В отдельном
PTY с временным XDG_CONFIG_HOME мастер показал установку только этого пакета;
проверка остановлена через q до sudo. Уже открытый пользователем старый мастер
не завершался агентом: его надо закрыть через q и запустить новую версию.

Прошли make check, make build, bash -n и регрессионный тест плана пакетов на
настоящем pacman. Скомпилированная на установленной libz небольшая C-проверка
compress2/uncompress восстановила исходные байты; headers/runtime сообщают
1.3.1.zlib-ng. Установка пакетов и удаление системных библиотек не выполнялись.

## FDPI 0.2.0 — конфликт служб, формы и первый запуск

Обнаружена фактическая причина отказа: запущены zapret.service и zapret2.service;
первый nfqws использует очередь 200, nfqws2 — 300. Системный FDPI 0.1.0 завершался
из-за занятой очереди, затем systemd ограничивал число запусков. Это не исправляется
одним reset-failed без устранения конфликта.

В 0.2.0 выделены очередь 24000 и mark 0x20000000; известные параллельные движки
проверяются до запуска. TUI предлагает подтвердить остановку, CLI требует
`start --replace`. При ошибке FDPI предпринимается восстановление ранее активных
служб. `enable --replace` отдельно разрешает замену их автозапуска. Перед явным
start/restart сбрасывается только failed-state FDPI. Известный конфликт даёт код
78; unit содержит RestartPreventExitStatus=78, предотвращая бессмысленный restart loop.
Смешивание новой управляющей части со старым /usr/bin/fdpi блокируется до обновления.

Новый отдельный TUI установки открывается на первом запуске версии. Стрелки и
пробел выбирают сервисы и опции, Enter подтверждает каждый реальный шаг. Пропуск
установки — явное действие; его маркер не является доказательством установленной
службы. Повторно открыть: fdpi setup или i. Основной интерфейс отдельно: fdpi tui.
Завершённый мастер освобождает setup.lock перед открытием основного TUI.

По умолчанию теперь YouTube, Steam и Discord. Удаляются только нетронутые
выключенные старые примеры, пользовательские домены/названия/стратегии сохраняются.
Новый сервис создаётся формой n: название, домены или URL, стратегия стрелками,
включение пробелом, сохранение Ctrl+S. Ссылки нормализуются до доменов, URL с
учётными данными отвергаются. Enter/e редактирует сервис; Del удаляет из черновика.

Фактически прошли:

- make check: форматирование, vet, все unit tests, race detector;
- make build, bash -n, проверка unit с подстановкой собранного executable;
- все 8 стратегий: настоящий nfqws dry-run ([вывод](evidence/engine-0.2.txt));
- настоящие namespace-тесты с новой очередью/mark: HTTP/HTTPS IPv4/IPv6,
  TCP split на veth, fail-open, SIGKILL и очистка ([вывод](evidence/netns-0.2.txt));
- тот же сетевой прогон с race detector ([вывод](evidence/netns-0.2-race.txt));
- в реальном PTY: первый запуск → установщик, стрелки и флажки, явный переход
  в основной TUI, создание «Мой сайт» из https://example.org/path без JSON,
  сохранение example.org, предложение остановить обе zapret-службы и отмена.

Регрессионные тесты покрывают запрет замены без согласия, reset-failed перед
start, восстановление двух прежних служб при искусственной ошибке запуска,
отдельную семантику enable, неуспех шага установщика без перехода дальше,
версионный marker, нормализацию доменов, флажки/стрелки формы, безопасную миграцию.
Исполнитель systemctl в этих тестах подставной; это не реальное переключение
системных служб. Работа packet engine в namespace проверена отдельно настоящая.

Установленный /usr/bin/fdpi на момент проверки остаётся версией 0.1.0 и failed;
запущенные zapret/zapret2 агентом не останавливались. Для применения исправления
нужно пройти системную установку 0.2.0 в новом TUI с sudo. Проверка нового unit
под настоящим systemd, переключения служб и reboot остаётся за этим шагом.


## FDPI 0.3.0 — nfqws2 и прямые проверки, 2026-11-08

Движок: zapret2 commit 9b9b929f837978173d787a5773a47a91d90f7f81.
Go vet, unit tests, race detector, сборка и настоящий dry-run восьми стратегий
прошли. Сетевые namespace-тесты передали точные HTTP/HTTPS данные IPv4/IPv6
и проверили реальные сегменты на veth. Дополнительный маршрут по fwmark
на интерфейс с MTU 1376 воспроизводит VPN/PBR. С bind-fix тест проходит,
контрольный прогон с удалёнными bind-fix ожидаемо завершается тайм-аутом.
См. evidence/netns-0.3-pbr.txt, netns-0.3-race.txt, netns-0.3-negative.txt.

На пользовательской машине установлен FDPI 0.3.0, служба работает с nfqws2.
Сохранены профили и их домены. Для прямых тестов временно добавлялись точечные
маршруты к адресам YouTube и исключения только этих адресов из Amnezia firewall.
После каждого прогона правила/маршруты удалены; VPN оставлен для связи с чатом.
DNS использовал системный резолвер. Это не тест всей машины с отключённым VPN.

База без стратегии и light не прошли. balanced успешно получила HTML
(977085 байт), JPEG (21011 байт) и JSON API анонимной главной (18102 байта).
Все три ответа HTTP 200, локальные адреса 192.168.31.131, а не адрес туннеля.
Стратегия balanced сохранена в системном и локальном профиле YouTube.
См. evidence/youtube-direct-0.3.json.

Отдельно yt-dlp получил метаданные через прямое соединение с исходным адресом
сетевой карты. Затем curl напрямую скачал диапазон 0-1048575 видеопотока AV1
(format 394): HTTP 206, 1048576 байт, локальный адрес 192.168.31.131.
Подписанный URL не публикуется. См. evidence/video-direct-0.3.json.
Это не доказывает полное воспроизведение видео в браузере, QUIC/HTTP3,
персональные рекомендации или доступ на других сетях.

Первый системный сценарий сравнения прервался из-за StartLimitBurst; cleanup
удалил временные правила и восстановил конфиг. Копирование старого бинарного
файла поверх выполняемого завершилось ETXTBSY. Повторный сценарий использовал
reset-failed перед каждым тестовым запуском и атомарное восстановление файла;
завершился успешно. Системный лимит перезапусков не отключался.

Amnezia нельзя отключать только через NetworkManager: её anchors могут сохранить
blockAll/blockDNS. Используйте штатное отключение в самом приложении Amnezia.
FDPI не удаляет глобально чужие правила и не заявляет, что сам обходит kill switch.


## FDPI 0.4.0 — TUI и Spotify Desktop

Общая рамка с палитрой FDPI применена к семи разделам, форме профиля,
редактору, подтверждению и установщику. Добавлена проверка границ каждого
раздела и формы в терминалах 40×15, 80×25 и 136×38. Растровые снимки в
assets/ получены с настоящего Bubble Tea в PTY, терминальные ячейки
отрисованы в PNG. Статус службы и автозапуска прочитан из systemd.
ВКЛ в таблице означает локально выбранный профиль, не результат доступа.

Профиль Spotify Desktop использует отдельную стратегию fake,multisplit,
позиции 1,midsld, badseq и два fake-повтора. HTTPS-запросы с физического
интерфейса получили: apresolve 200, accounts 301, open.spotify.com 302,
i.scdn.co 403 на запрос корня. HTTP 403 не объявлен успешной загрузкой обложки.
Отдельные аудиоданные, нативный AP-протокол и воспроизведение не проверены.
Клиент Spotify оставлен на паузе. Временные маршруты и исключения удалены.

Новый профиль принят настоящим nfqws2 через dry-run. Go vet, тесты,
race detector и реальные namespace-проверки с конкурирующим маршрутом
и MTU 1376 прошли. Системная служба обновлена и работает с версией 0.4.0.
См. evidence/spotify-direct-0.4.json и netns-0.4-race.txt.

Для публичной версии отчётов локальные адреса заменены на документальные,
а домашний каталог и путь резервной копии скрыты. Числа байт, HTTP-коды
и результаты тестов сохранены. Оригинальные локальные измерения остаются
в рабочем каталоге сессии.
