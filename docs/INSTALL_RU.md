# Установка FDPI на CachyOS / Arch Linux

Версия 0.4.0 использует внешний nfqws2 и Lua. При обновлении выполните
`make engine`, `make check build`, затем `sudo make install` и
`sudo systemctl restart fdpi.service`. Установщик сохраняет системный конфиг.
Для проверки главной: `fdpi test-service youtube`. HTTP 200 страницы
не означает, что API и видео доступны.


## Первый запуск: отдельный TUI установщика

Закройте прежний текстовый мастер клавишей `q`, если он ещё открыт, и запустите:

```bash
fdpi
```

При первом запуске версии откроется установщик. Он доступен отдельно командой
`fdpi setup` и клавишей `i` из основного интерфейса. Чтобы сразу открыть основной
TUI без предложения установки, используйте `fdpi tui`.

1. Стрелками выберите **«Начать / обновить установку»**, нажмите Enter.
2. Пробелом отметьте YouTube, Steam, Discord или существующие свои сервисы.
   Сохранение conntrack, HTTPS-проверка и автозапуск выбираются отдельными флажками.
3. Если уже работают zapret/zapret2, для запуска FDPI отметьте **разрешение замены**.
   Оно разрешает остановить эти службы; при выбранном автозапуске FDPI также
   отключить их автозапуск. Без флажка мастер их не меняет. При неудачном запуске
   FDPI будет предпринято восстановление ранее работающих служб.
4. Выберите **«Продолжить установку»**. Перед каждым действием видны команда и
   описание. Enter запускает текущий шаг; q завершает мастер между командами.
5. Пароль sudo вводите только в терминале. После завершения можно открыть основной TUI.

Действия выполняются последовательно: зависимости с учётом совместимых пакетов,
проверки, сборка FDPI и nfqws, установка, при необходимости conntrack, затем
применение выбранных сервисов, запуск и фактическая проверка состояния systemd.
После ошибки шаг не засчитывается: видны последние строки вывода, Enter повторяет
тот же шаг. `n` пропускает только необязательную HTTPS-проверку.

Чтобы установить только файлы, оставьте все сервисы выключенными. Автозапуск
автоматически требует сохранения conntrack после перезагрузки. Установщик
сохраняет существующий системный конфиг; прежние пользовательские профили
с изменёнными доменами, именами или стратегиями сохраняются.

Для своего сервиса откройте основной TUI → Tab до «Сервисы» → **n**:

- название — любое понятное имя;
- домены или http/https-ссылки — по одному на строку (пути ссылок отбрасываются);
- стратегия — ←/→;
- включение — пробел;
- Tab — следующее поле, Ctrl+S — сохранить, Esc — отменить.

Затем `a` применяет черновик к системной службе. Обрабатываются домены, а не
процессы приложений. Упрощённая форма не требует редактирования JSON.

`fdpi setup --source /путь/к/fdpi` выбирает другой каталог исходников;
`fdpi setup --guide` показывает ручную инструкцию; `fdpi setup --text`
оставляет текстовый мастер для диагностики.

Служба может продолжать работу после выхода. Остановить: `fdpi stop`.
Первое предложение установки показывается до успешного прохождения или явного
выбора «Открыть основной интерфейс без установки» для этой версии. Полный журнал
возобновления шагов не реализован: при повторном запуске состояние проверяется заново.

Ниже — действия для ручного выполнения. Без установленного движка интерфейс
не обрабатывает трафик.

## 1. Откройте каталог проекта

```bash
git clone https://github.com/futureUnd1ground/fdpi.git ~/fdpi
cd ~/fdpi
```

Остальные команды сборки выполняйте в этом каталоге. Если перенесли проект,
откройте новую папку с файлами `Makefile` и `go.mod`.

## 2. Установите зависимости

```bash
sudo pacman -S --needed base-devel go git pkgconf nftables libnetfilter_queue libnfnetlink libmnl sudo
```

В CachyOS уже установленный `zlib-ng-compat` подходит вместо `zlib`: заменять его
не нужно. Мастер использует `pacman -T` и устанавливает только отсутствующие
зависимости, учитывая совместимые пакеты. Проверка библиотеки: `pacman -T zlib`
(пустой вывод означает, что зависимость удовлетворена), API: `pkg-config --exists zlib`.
Если ни одной реализации нет, установите подходящую для своей системы —
`zlib-ng-compat` в CachyOS или `zlib` в Arch.

Пароль sudo вводится только в вашем терминале. В чат его отправлять не нужно.

## 3. Проверьте и соберите программу

Выполняйте команды по очереди. Переходите к следующей только после успешного завершения.

```bash
make check
make build
make engine
```

`make check` запускает проверки; `make build` собирает FDPI; `make engine`
скачивает закреплённые исходники zapret/nfqws и собирает обработчик пакетов.
Для загрузки исходников нужен интернет. Ошибка на этом шаге означает, что
сетевой движок ещё не готов, даже если интерфейс открывается.

## 4. Установите файлы в систему

```bash
sudo make install
```

Будут установлены `/usr/bin/fdpi`, `/usr/lib/fdpi/nfqws` и `fdpi.service`.
Существующие системные настройки сохранятся. Служба автоматически не запустится.
**Интерфейс запускайте обычной командой `fdpi`, без sudo.**

## 5. Проверьте учёт соединений

Он нужен, чтобы отправлять в движок только первые пакеты соединения.

```bash
sysctl net.netfilter.nf_conntrack_acct
```

Если ответ заканчивается на `= 1`, для текущего запуска ничего менять не нужно.
Если указано `= 0`, включите:

```bash
sudo sysctl -w net.netfilter.nf_conntrack_acct=1
```

Для сохранения после перезагрузки откройте собственный файл настроек:

```bash
sudoedit /etc/sysctl.d/70-fdpi.conf
```

Добавьте строку, сохраните файл и закройте редактор:

```ini
net.netfilter.nf_conntrack_acct=1
```

Фоновая служба FDPI не меняет этот параметр; мастер может включить его после подтверждения. После его включения проверяйте
новые подключения: старые соединения могли быть созданы без счётчиков.

## 6. Включите один сервис для первой проверки

Начните с YouTube и лёгкой стратегии:

```bash
fdpi config enable youtube on
fdpi config strategy youtube light
fdpi apply
fdpi start
```

Пользовательские настройки создадутся автоматически. `light` — постоянный ID
стратегии «Лёгкая». `apply` проверяет параметры и переносит черновик в системный
конфиг, `start` запускает обработку. Для административных действий запрашивается sudo.

Если работают zapret/zapret2, обычный start сообщит о конфликте, сохранив их.
Для явного подтверждения остановки и запуска FDPI: `fdpi start --replace`.
`fdpi enable --replace` отдельно подтверждает замену их автозапуска.
Лимит неудачных запусков FDPI сбрасывается перед явным start/restart.

Проверьте состояние и доступность:

```bash
fdpi status
sudo /usr/bin/fdpi doctor
fdpi test youtube.com
```

Ожидается состояние службы «работает». В диагностике изучите пункты с `[!]`:
отдельная отметка возможного конфликта очередей может относиться к самому FDPI.
HTTPS-ответ ещё не доказывает работу видео или обход DPI вашего провайдера.

## 7. Откройте интерфейс

```bash
fdpi
```

| Клавиша | Действие |
|---|---|
| Tab | Следующий раздел |
| ↑/↓ или j/k | Выбор |
| Пробел | Включить/выключить сервис в черновике |
| e | Изменить профиль или стратегию |
| Ctrl+S / Esc | Сохранить форму / отменить |
| a | Применить настройки к сети |
| s | Запустить/остановить службу |
| d | Диагностика |
| q | Закрыть интерфейс |

Закрытие интерфейса не останавливает службу. Меню и сообщения на русском;
команды, ID и ключи JSON сохраняют английские имена для совместимости пресетов.
Подробные сообщения ОС и upstream nfqws выводятся в исходном виде.

## 8. Включите автозапуск после успешной проверки

```bash
fdpi enable
```

Это включает запуск вместе с системой. Саму перезагрузку для проверки выполните
позже, когда убедитесь в работе выбранной стратегии.

## Если возникли проблемы

Остановить обработку и удалить собственные сетевые правила:

```bash
fdpi stop
```

Вернуть предыдущие системные настройки:

```bash
fdpi rollback
```

Посмотреть журнал и диагностику:

```bash
fdpi logs
sudo /usr/bin/fdpi doctor
```

FDPI не сбрасывает firewall целиком и не отключает IPv6/QUIC глобально.
Если `sudo` сообщает об ошибке авторизации, выполните команду самостоятельно
в терминале. Установка с root в текущей сессии не выполнялась.

## Удаление

В каталоге проекта:

```bash
sudo make uninstall
```

Бинарники и служба удалятся; `/etc/fdpi` и `~/.config/fdpi` сохранятся.
Если перестал быть нужен созданный вами sysctl-файл, удалите его отдельно,
учитывая, что учёт conntrack может использоваться другими программами.

Полный перечень фактических проверок и ограничений — в [VALIDATION.md](VALIDATION.md).
