# Палитры рабочего стола

FDPI читает экспортированные JSON, не анализирует обои и не требует Hyprland.
Тема меняет только TUI. Имя хранится в ~/.config/fdpi/theme.json.
`r` перечитывает палитру без рестарта движка; чтения на каждый кадр нет.

При Auto источники идут в порядке:

1. `$XDG_CACHE_HOME/wallust/colors.json`;
2. `$XDG_CACHE_HOME/wal/colors.json` (pywal);
3. `$XDG_CONFIG_HOME/fdpi/matugen.json`;
4. встроенная Catppuccin Mocha.

Если XDG-переменные не заданы, Go использует стандартные ~/.cache и ~/.config.
`fdpi theme pywal` выбирает источник явно; при отсутствующем/неверном файле
интерфейс использует fallback, его фактическое имя видно в заголовке.
Внешние программы не вызываются. Их версии/конфиги отличаются: задайте экспорт
на нужный путь в своей wallust/matugen-конфигурации.

Минимальный совместимый JSON для любого источника:

```json
{
  "special": {"background":"#1e1e2e", "foreground":"#cdd6f4"},
  "colors": {"color4":"#89b4fa"}
}
```

Также принимается canonical matugen JSON:

```json
{
  "colors": {
    "dark": {
      "background":"#101414",
      "on_background":"#dfe4e4",
      "primary":"#80d5d5"
    }
  }
}
```

Цветовые значения могут быть строками или объектами `{"hex":"#RRGGBB"}`.
Для светлой matugen-палитры экспортируйте выбранную ветку как `colors` без
обёртки `dark`; присутствующая `dark` имеет приоритет. Исходный цвет фона
сохраняется, foreground корректируется до контраста ≥4.5:1, accent ≥3:1.
При неверных цветах/формате файл отвергается целиком.

Terminal использует ANSI цвета 0/7/4; их контраст задаёт сам терминал.
Для Mocha/Latte и остальных встроенных схем внешние файлы не нужны.
Набор фактически проверенных схем импорта покрывают unit tests, а не запуск
самих генераторов обоев на пользовательском рабочем столе.
